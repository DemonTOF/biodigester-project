Configuración de PocketBase para el Biodigester

Supuesto: ya tienes PocketBase desplegado y corriendo en https://pocketbase-production-292f.up.railway.app/ con acceso de administrador. Este documento explica cómo dejarlo listo para la app:

  1. Crear la colección feeds e importar el histórico desde feeds.csv.
  2. Configurar el cron que cada N minutos descarga lo nuevo desde ThingSpeak.
  3. Exponer GET /api/feeds con filtros de fecha para la app Flutter.
Contexto: El canal de ThingSpeak (id 2621081) solo expone vía API los últimos 8000 feeds e ignora start_id/end_id. Por eso el histórico completo (85.958 filas) se carga una vez desde el CSV, y el cron solo inserta los entry_id nuevos.

Arquitectura

feeds.csv ──(import script)──► PocketBase (ya corriendo)
                                      │
ThingSpeak ──(cron cada N min)──────►│  inserta entry_id nuevo
                                      │
App Flutter ◄── GET /api/feeds?start=&end= ┘

Prerrequisitos

  • Acceso de administrador a https://pocketbase-production-292f.up.railway.app/.
  • Python 3 instalado localmente (para el script de importación).
  • El archivo feeds.csv en tu máquina local.

Paso 1 — Obtener token de administrador

En el Admin UI crea/usa tu superusuario. Luego obtén el token (lo necesitas en los Pasos 2 y 3):

PB_URL="https://pocketbase-production-292f.up.railway.app"

curl -X POST "$PB_URL/api/admins/auth-with-password" \
  -H "Content-Type: application/json" \
  -d '{"identity":"TU_EMAIL_DE_ADMIN","password":"TU_PASSWORD_DE_ADMIN"}'

Guarda el token devuelto y úsalo como $PB_TOKEN en los siguientes pasos.

Paso 2 — Crear la colección feeds

Reemplaza $PB_TOKEN por el token del Paso 1:

PB_URL="https://pocketbase-production-292f.up.railway.app"

curl -X POST "$PB_URL/api/collections" \
  -H "Authorization: $PB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "name": "feeds",
  "type": "base",
  "schema": [

    {"name":"created_at","type":"date","required":true},
    {"name":"field1","type":"number"},
    {"name":"field2","type":"number"},
    {"name":"field3","type":"number"},
    {"name":"field4","type":"number"},
    {"name":"field5","type":"number"},
    {"name":"field6","type":"number"},
    {"name":"field7","type":"number"},
    {"name":"field8","type":"number"}

listRule: "" hace que cualquiera pueda leer (necesario para la app). Si quieres protegerlo, usa un token de API en su lugar.

Paso 3 — Importar feeds.csv

Guarda este script como import_feeds.py en tu máquina local (junto a feeds.csv):

import csv, os, requests
from concurrent.futures import ThreadPoolExecutor
from datetime import datetime, timezone

PB_URL = os.environ["PB_URL"].rstrip("/")
TOKEN  = os.environ["PB_TOKEN"]
HEADERS = {"Authorization": TOKEN, "Content-Type": "application/json"}

def to_num(v):
    if v is None or v.strip() == "" or v.strip().lower() == "nan":
        return None
    try:
        return float(v)
    except ValueError:
        return None

def to_iso(s):
    s = s.strip().replace(" UTC", "").strip()
    dt = datetime.strptime(s, "%Y-%m-%d %H:%M:%S").replace(tzinfo=timezone.utc)
    return dt.isoformat()

def post(rec):
    try:
        r = requests.post(f"{PB_URL}/api/collections/feeds/records",
                          json=rec, headers=HEADERS, timeout=30)
        if r.status_code >= 400:
            print("ERR", r.status_code, r.text[:200])
    except Exception as e:
        print("EXC", e)

batch = []
with open("feeds.csv", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        rec = {
            "entry_id": int(row["entry_id"]),
            "created_at": to_iso(row["created_at"]),
            "field1": to_num(row["field1"]),
            "field2": to_num(row["field2"]),
            "field3": to_num(row["field3"]),
            "field4": to_num(row["field4"]),
            "field5": to_num(row["field5"]),
            "field6": to_num(row["field6"]),
            "field7": to_num(row["field7"]),
            "field8": to_num(row["field8"]),
        }
        batch.append(rec)
        if len(batch) >= 500:
            with ThreadPoolExecutor(max_workers=20) as ex:
                ex.map(post, batch)
            print("imported", len(batch))
            batch = []
    if batch:
        with ThreadPoolExecutor(max_workers=20) as ex:
            ex.map(post, batch)
        print("imported final", len(batch))

print("DONE")

Ejecuta:

export PB_URL="https://pocketbase-production-292f.up.railway.app"
export PB_TOKEN="token-obtenido-en-paso-1"
python3 import_feeds.py

Verifica el conteo:

curl "$PB_URL/api/collections/feeds/records?perPage=1&fields=id" \
  -H "Authorization: $PB_TOKEN"

Paso 4 — Variables de entorno de ThingSpeak

En el lugar donde corre PocketBase (Railway → Variables, o el entorno del host), define:

THINGSPEAK_CHANNEL_ID=2621081
THINGSPEAK_API_KEY=DS0O5JWOPSREYKM7

El cron las lee con $os.getenv(...). Reinicia el servicio si es necesario para que carguen.

Paso 5 — Cron: sincronizar ThingSpeak cada N minutos

Abre el Admin UI → Settings → Files (editor de pb_hooks) y crea sync_thingspeak.pb.js con este contenido:

cronAdd("sync_thingspeak", "*/5 * * * *", function() {
  try {
    var channelId = $os.getenv("THINGSPEAK_CHANNEL_ID") || "2621081";
    var apiKey = $os.getenv("THINGSPEAK_API_KEY") || "DS0O5JWOPSREYKM7";

    var last = $app.findRecordsByFilter("feeds", "", "-entry_id", 1, 0);
    var lastEntryId = last.length ? last[0].get("entry_id") : 0;

    var url = "https://api.thingspeak.com/channels/" + channelId +
              "/feeds.json?api_key=" + apiKey + "&results=8000";
    var res = $http.send({ url: url, method: "GET", timeout: 30 });
    var data = res.json();
    var feeds = data.feeds || [];

    function parseNum(v) {
      if (v === null || v === "" || v === "nan" || v === "NaN") return null;
      var n = parseFloat(v);
      return isNaN(n) ? null : n;
    }

    var inserted = 0;
    for (var i = 0; i < feeds.length; i++) {
      var f = feeds[i];
      var id = f.entry_id;
      if (id <= lastEntryId) continue;
      var rec = new Record($app.collection("feeds"), {
        "entry_id": id,
        "created_at": f.created_at,
        "field1": parseNum(f.field1),
        "field2": parseNum(f.field2),
        "field3": parseNum(f.field3),
        "field4": parseNum(f.field4),
        "field5": parseNum(f.field5),
        "field6": parseNum(f.field6),
        "field7": parseNum(f.field7),
        "field8": parseNum(f.field8)
      });
      $app.save(rec);
      inserted++;
    }
    console.log("sync_thingspeak: inserted", inserted, "new feeds");
  } catch (e) {
    console.log("sync_thingspeak error:", e);
  }
});

El cron corre cada 5 minutos (*/5 * * * *). Para cada 10 min usa */10 * * * *.

Paso 6 — Endpoint GET para la app

En el mismo editor (Settings → Files) crea feeds_endpoint.pb.js:

routerAdd("GET", "/api/feeds", function(e) {
  try {
    var q = e.request.url.query();
    var start = q.get("start");
    var end = q.get("end");
    var limit = parseInt(q.get("limit") || "100000");

    var filter = "";
    if (start) filter += "created_at >= '" + start + "'";
    if (start && end) filter += " && ";
    if (end) filter += "created_at <= '" + end + "'";

    var records = $app.findRecordsByFilter("feeds", filter, "created_at", limit, 0);
    var items = [];
    for (var i = 0; i < records.length; i++) {
      var r = records[i];
      items.push({
        "entry_id": r.get("entry_id"),
        "created_at": r.get("created_at"),
        "field1": r.get("field1"),
        "field2": r.get("field2"),
        "field3": r.get("field3"),
        "field4": r.get("field4"),
        "field5": r.get("field5"),
        "field6": r.get("field6"),
        "field7": r.get("field7"),
        "field8": r.get("field8")
      });
    }
    return e.json(200, { "count": items.length, "items": items });
  } catch (err) {
    return e.json(500, { "error": String(err) });
  }
});

Al no declarar middleware de autenticación, la ruta es pública. Guarda los archivos; PocketBase recarga los hooks automáticamente.

Paso 7 — Probar

Prueba el endpoint (no requiere token por ser público):

PB_URL="https://pocketbase-production-292f.up.railway.app"

# Primeras 5 filas
curl "$PB_URL/api/feeds?limit=5"

# Con filtro de fechas (ISO 8601)
curl "$PB_URL/api/feeds?start=2026-01-01T00:00:00Z&end=2026-02-01T00:00:00Z"

Verifica el cron en el Dashboard → Settings → Crons (aparece sync_thingspeak). Puedes dispararlo manualmente para probar.

Paso 8 (opcional) — Apuntar la app Flutter a PocketBase

El endpoint devuelve exactamente los campos que la app usa (entry_id, created_at, field1..field8). Para usarlo, se reemplaza ThingSpeakSyncService por un servicio que haga GET $PB_URL/api/feeds?start=&end= y guarde en la base local drift. Es un cambio de la app que podemos hacer en otro paso; el backend queda listo y funcionando.

Solución de problemas

SíntomaCausa / Solución
El cron no apareceEl archivo debe terminar en .pb.js y estar guardado en Settings → Files. Revisa los logs.
504 en /api/feedsConsulta muy grande. Usa ?start=&end= o ?limit=.
Import lentoAumenta max_workers en el script o reduce el tamaño de lote.
Duplicadosentry_id es único; PocketBase rechazará duplicados (error 400, ignorado por el script).
Seguridad: listRule: "" expone todos los datos públicamente. Si esto no es deseado, crea un API token en PocketBase y exígelo en el endpoint y en la app en lugar de dejarlo abierto.
